# 認知負荷と予定調和

PRの認知効率は、論証を追跡する際に、不必要な切り替え・記憶・推論を要求しないかという観点から評価する。

\[
C=(C_{\mathrm{switch}},C_{\mathrm{memory}},C_{\mathrm{inference}})
\]

本モデルでは、切り替え、記憶、推論の順に重視する設計仮説を置く。これは経験的に確立した普遍的な順位や、数値的な重み付けではない。個人差があるため、数値測定を必須とせず、負荷を発生させる論理構造を評価する。

## 関心の連続性

関心とは、現在追跡している命題、Requirements、目的である。同じ目的について、要求から証拠までの論証が連続することが望ましい。

\[
r_1\rightarrow q_1\rightarrow b_1\rightarrow i_1
\rightarrow \text{Evidence}_1
\]

ファイルや技術レイヤーが変わっても、目的が連続していれば、必ずしも関心の切り替えではない。ファイル単位のまとまりと、論証単位のまとまりは区別する。

## 予定調和

予定調和とは、次に必要な情報が、それまでの理解から自然に予測でき、必要な時点で提示されることである。

- 前提が利用可能な順序で論証する。
- 同じ目的についての論証を可能な限り連続させる。
- 共通の前提を補題として切り出し、再利用する。
- 明示的な参照によって、不要な先読みを避ける。
- 不必要な重複や往復を避ける。

この考え方を、Commit分割、PR分割、Bodyの構成、参照の配置に適用する。参照を増やすこと自体が目的ではなく、必要な前提と証拠へ自然に到達できる構造を作る。

## Repository Load

\[
H_{\mathrm{repo}}(S_f;K,T)
\]

最終リポジトリを理解・利用・変更するための認知負荷である。\(S_f\) は最終状態、\(K\) は利用者の知識、\(T\) は行うタスクを表す。

コードだけでなく、文書・テスト・履歴・参照経路も理解の負荷に関わるため、評価対象は実装 \(\mathcal I_f\) より広い最終状態として扱う。

最終状態と利用可能なアクセス経路、利用者の知識、タスクが同じなら、PRの分割だけではRepository Loadは変わらない。一方、分割やマージ方法によって残る履歴やアクセス経路が変わるなら、この同一条件は成立しない。

## Review Load

\[
C_{\mathrm{review}}(\mathcal P,\pi,K_0)
\]

PRの変更を理解し、受け入れ判断を行うための認知負荷である。\(\mathcal P\) は対象となるPR群、\(\pi\) は提示・閲覧の順序、\(K_0\) はレビュー開始時の知識を表す。

Review Loadは、PR分割、Commit構造、提示順序、参照構造によって変化する。[知識の配置](./knowledge-placement.md)は、レビュー時の説明を整えることと、将来の知識へのアクセスを整えることの混同を避けるための原則でもある。

## 構造の比較

同じ論証と必要な知識へのアクセスを維持したまま、目的の切り替えや不必要な前提保持を減らせるなら、その構造を優先できる。

一方、切り替えを減らすと重複が増えるなど、複数の指標が競合する場合もある。一意の最適解が存在するとは限らず、非支配な構造の扱いは[未定義事項](./open-questions.md)である。
